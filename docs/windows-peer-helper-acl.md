# Windows peer helper path check

`inspectWindowsPeerHelperAcl(helperPath, expectedSha256)` is a read-only installer check for the one-shot named-pipe helper. `WindowsAgentPipeRegistry` requires an installer-pinned SHA-256 for its native path and runs this check for each attempted one-shot opening. It then refuses native launch because the trusted agent launcher and its network boundary have not been verified. Only synthetic helper injection in isolated tests can open a pipe today.

The installer must place `s-gw-windows-peer-identity.exe` on a local fixed drive. The executable and every directory back to the drive root must be owned by SYSTEM, Administrators, or Windows Modules Installer (TrustedInstaller), must have a DACL, and must not be a reparse point. Untrusted principals may not change or delete any component. They may create siblings in ancestors above the helper's immediate parent, since those rights do not replace existing protected components. They may not create files or directories beside the helper, where a sibling DLL could be loaded. The check considers only ACEs effective on each existing object; inherit-only ACEs affect future children, while effective inherited grants are checked. The expected SHA-256 must come from a trusted installer manifest, not from an agent request or a file beside the helper. Unknown and conditional ACE types fail closed.

The pin must be supplied by the trusted installer or broker startup, never an agent request. Keep the installed path protected while the agent is alive. Raw ACE inspection is a conservative path check, not an `AccessCheck` of the actual agent token. The check alone does not establish that the agent is non-administrative or that its AppContainer package, Job Object, WFP rules, and named-pipe identity all match one broker session. Validate effective access with the actual agent token on Windows, including inherited groups, owner rights, hard-link access, and a helper update during launch. Test two concurrent AppContainers and dedicated accounts, helper replacement and reparse attempts, cross-session pipe use, IPv4/IPv6 egress, rule loss, revocation, and agent teardown before enabling native launches.

The Windows ACL CI shard compiles the one-shot helper with MSVC. This catches native build failures but does not run a real AppContainer exchange or establish confinement.
